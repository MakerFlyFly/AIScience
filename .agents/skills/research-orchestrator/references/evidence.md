# 文献、证据与主张协议

## 检索循环

1. 确认 G0 有效且公开查询边界允许检索。
2. 在执行前记录查询、数据库/工具、时间范围、过滤条件、排序规则、停止条件和预算。
3. 保存结果快照摘要与可复查标识；不要只保留最终入选文献。
4. 核验来源身份与版本，分别记录 metadata、正文可得性和检索快照摘要。
5. 建立证据卡，映射到主张；主动检索反证、阴性结果、撤稿与勘误。
6. 当达到预先声明的饱和/预算/时间停止条件时结束，不以“支持预期结论”为停止理由。

## 来源记录

每条来源记录 DOI、arXiv ID 或稳定 URL、题名、作者、年份、版本、访问时间、访问级别、许可、全文是否可用、撤稿/勘误状态，以及 metadata/正文/快照各自的来源与哈希。只有许可允许时才能将全文放入仓库或交付包。

优先级通常为同行评议原始研究、权威数据/标准、系统综述，再到预印本和摘要。摘要证据必须标记 `abstract_only`，不得支持需要正文细节才能成立的强主张。博客、搜索摘要和代理输出只能作为线索，不能独立支撑学术结论。

## 证据卡

证据卡至少包含：不可变 ID/版本、来源版本、中文释义、精确页/节/图/表定位、证据方向（支持/反驳/背景）、适用范围、方法限制、抽样与偏倚风险、是否仅摘要、创建者和依赖哈希。释义不得扩大原文结论。

## 主张台账

以下内容必须进入 claim ledger：摘要、结果、讨论、结论中的实质陈述，以及全文中的新颖性、定量、比较、因果、泛化、安全和影响结论的背景事实。

每条主张记录英文规范文本、中文阅读文本、类型、支持状态、证据卡/运行引用、局限、版本、`supersedes` 和文本哈希。支持状态使用 `supported`、`refuted`、`mixed`、`hypothesis`、`inference`、`insufficient`；后三者不得写成已证实事实。

主张版本不可覆写。英文文本变化时创建新版本并将对应中文标为 stale；来源撤稿、勘误或哈希变化时，使依赖主张与 Gate 过期。

## 假设谱系

生成、反思、相对排名和演化都创建新对象，记录父节点、证据与反证、可证伪预测、区分性实验、淘汰理由和负面结果。排名只是探索启发，不能代替证据。

## 安全与脱敏

写入 Git 前扫描密钥、令牌、PII、受限内容和绝对本地路径。不要为低熵敏感原文保存可猜测的普通 SHA-256；使用脱敏引用或受控存储标识。无法安全记录时标为 `unknown` 并请求必要的 G1。
